# ExpertTrader

This is a workspace for collaborating with Claude on ExpertTrader projects.

## 教師あり学習(`train.py`)の実行手順

マルチモーダル(画像+表形式特徴量)でLong/Hold/Short分類とリスク幅(%)回帰を同時に学習する`train.py`の実行方法です。`labeled_data/*_{mode}_scaled.csv`と`images/{SYMBOL}/{mode}_MTF/`の画像が事前に用意されている前提です。

### 基本的な実行方法

```bash
python train.py --mode medium
```

### 引数一覧

| 引数 | 必須 | デフォルト | 説明 |
|---|---|---|---|
| `--mode` | 任意 | `medium` | 学習対象の時間軸。`short` / `medium` / `long`のいずれか。`labeled_data/*_{mode}_scaled.csv`を自動検出する |
| `--epochs` | 任意 | `50` | 学習エポック数 |
| `--batch_size` | 任意 | `32` | バッチサイズ |
| `--lr` | 任意 | `0.001` | 学習率(Adam) |
| `--start` | 任意 | なし(全期間) | 学習データの開始日(`yyyy-mm-dd`) |
| `--end` | 任意 | なし(全期間) | 学習データの終了日(`yyyy-mm-dd`) |
| `--freeze-backbone` | 任意 | `none` | ResNet50バックボーンの凍結範囲。`none` / `stem` / `early` / `early_plus_layer3`(詳細は下記) |

対象銘柄は固定の7銘柄(GBPUSD, EURUSD, USDJPY, AUDUSD, GBPJPY, EURJPY, GOLD)で、`labeled_data/`内に見つかったものを自動的にまとめて学習します。

既存の`saved_model/model_{mode}.pth`が見つかった場合は、その続きから継続学習します(無ければ新規学習)。

### `--freeze-backbone`について(2026-11-13追加)

ResNet50バックボーンを丸ごとfine-tuningすると学習時間・GPUメモリのコストが大きいため、どこまで凍結するかを選べるようにしたオプションです。

| 値 | 凍結範囲 | 想定される精度リスク |
|---|---|---|
| `none`(デフォルト) | なし(従来通り全層fine-tuning) | 基準点。リスクなし、学習コストは最大 |
| `stem` | conv1, bn1 | 最小限 |
| `early` | conv1, bn1, layer1, layer2 | 推奨の出発点 |
| `early_plus_layer3` | 上記 + layer3 | `early`より精度低下リスクが高い想定 |

転移学習の一般的な知見では、CNNの浅い層(conv1・layer1・layer2)は画像ドメインが変わっても転用しやすい汎用的な特徴を学習しており、深い層(layer3・layer4)はImageNet(自然画像)に特化した特徴を学習しているため、ローソク足チャート画像のような異なるドメインではfine-tuningが必要になりやすい、という考え方に基づく選択肢です。精度への実際の影響はこの環境では検証できていないため、`none`との比較は実際の学習結果(val_class_loss/val_risk_loss)で判断してください。

**凍結設定を変えて継続学習する場合の挙動**: モデルの重みは凍結設定に関わらずそのまま復元されますが、前回学習時と`--freeze-backbone`の値が異なる場合、optimizerの内部状態(モーメンタム等)のみ初期化し直されます(PyTorchの仕様上、凍結範囲が変わると学習対象パラメータの数が変わり、そのまま復元できないため)。学習そのものは継続され、エポック数やベストスコアの記録は失われません。

**凍結を変更する際の方針**:
- 凍結設定による精度への影響を確認したい場合 → 同条件で複数の設定を**新規学習**として独立に実行し比較する(継続学習では前段の学習分のアドバンテージが混ざり、純粋な比較にならない)
- 方針を決めた後、本番の学習を継続する場合 → 凍結を強める方向(例: `none`→`early`)、弱める方向(例: `early`→`none`、いわゆるprogressive unfreezing)のどちらも継続学習で問題ない。特に弱める方向(凍結解除)は転移学習で広く使われる手法で、むしろ最初から全層学習するより良い結果になることもある。解除する際は`--lr`を少し下げることを推奨
- 既存モデル(今回の`--freeze-backbone`導入前に学習したもの)をそのまま継続する場合は、`--freeze-backbone none`(デフォルト)を指定する。学習時に凍結の概念が無かった状態からの継続なので、これが最も挙動の変化が小さい選択

### 運用上の注意点

- **既存モデルの読み込みに失敗した場合は学習が停止します**(2026-11-13の修正)。以前は読み込み失敗時に静かに新規学習へフォールバックしていましたが、継続学習のつもりが気づかないまま最初からやり直しになる事故を防ぐため、現在はログに`❌ 既存モデルの読み込みに失敗しました`と出力し、学習を中止します。本当に新規学習したい場合は、既存の`saved_model/model_{mode}.pth`を退避・削除してください。
  - 注意: ローカルの`saved_model/model_{mode}.pth`を削除しても、Google Drive側(`/content/drive/MyDrive/FX_AI_Models/model_{mode}.pth`)に古いモデルが残っていると、それが自動的に復元されて読み込まれます。完全に新規学習したい場合は、Drive側のファイルも退避・削除してください。
- 画像データは初回実行時に検証(存在確認+読み込み確認)され、結果は`dataset_cache/`以下に台帳として保存されます。2回目以降は新規追加分のみ検証するため大幅に高速化されます。台帳はGoogle Driveにもバックアップされ、ローカルに無い場合は自動的に復元されます。
  - 前提: `generate_images.py`は既存タイムスタンプの画像を上書きしない設定(`OVERWRITE = False`)で運用している場合のみ、この台帳は常に正しい状態を保ちます。
- Google Drive(FUSEマウント)への接続が一時的に切断された場合、データ読み込み・モデル保存等は自動的に時間を空けて再試行します(最大5回、10→20→40→80→160秒間隔)。
- `nn.BatchNorm1d`の制約上、学習時にバッチサイズが1件になったバッチ(データ終端の半端なバッチや、画像読み込み失敗サンプルの除外等で発生)はスキップされ、ログに警告が出力されます。検証(validation)時はこの制約がないため影響ありません。
